# Pig-6 на Rust

Rust-реализация [VitaliiV-V/Pig6bot](https://github.com/VitaliiV-V/Pig6bot),
исходный коммит `41305c9b6f3d956df26ebddb769b7404f1b9250e`.
Исходная Python-версия доступна в репозитории по ссылке выше.
Здесь публикуются Rust-код, тесты и общие ресурсы сайта.
Для работы Python и supervisord не требуются.

## Запуск

Нужны Rust 1.85+ и компилятор C для встроенного SQLite. Проверенная локальная
сборка использует Rust 1.99.1 и MSVC; Docker собирает тот же Rust.
Команды выполняются из корня проекта: здесь находятся `web/`, `assets/`,
`dict.json` и `olymps.json`.

```sh
cp .env.example .env
# Заполните токены, OWNER_ID, MAIN_CHANNEL_ID и остальные нужные параметры.
cargo build --locked --release
cargo run --locked --release -- all
```

`all` запускает HTTP-сервер и ботов, для которых заданы токены.
Для отдельного бота его токен обязателен. `OWNER_ID` и `MAIN_CHANNEL_ID`
нужны для запуска ботов; веб-сервер запускается и без Telegram.
Один токен нельзя использовать для нескольких ботов.

```sh
cargo run -- web                         # только HTTP, порт 2322
cargo run -- main                        # основной бот + HTTP
cargo run -- cert                        # подписи Ed25519
cargo run -- logs                        # рассылка логов
cargo run -- jday                        # протокол судного дня
cargo run -- ai                          # Jarvis, нужен GEMINI_API_KEY
cargo run -- check-config                # проверка и создание файлов состояния
cargo run -- all --data-dir data         # отдельная папка состояния
```

`--env-file` выбирает файл окружения, `--web-dir` — каталог веб-страниц.
Переменные уже запущенного процесса имеют приоритет над `.env`.
`BIND_ADDR`, `WEB_SITE`, `GEMINI_MODEL` и `RUST_LOG` настраивают адрес,
публичные ссылки, модель Gemini и журналирование.

В этой рабочей папке установлен локальный Rust в `.tools/` и подготовлен
`scripts/run.ps1`. Например, `./scripts/run.ps1 web` запускает сервер
с уже загруженными зависимостями. Обычная установка Rust использует команды выше.

## Docker

```sh
cp .env.example .env
docker compose up --build -d
docker compose logs -f
```

Состояние сохраняется в `./data`, HTTP доступен на `http://localhost:2322`.
Редактируемая политика безопасности подключена отдельным томом.
Остановка через Ctrl+C или Docker отменяет задачи всех сервисов.
При ошибке запуска одного сервиса процесс завершается, и Docker перезапускает его.

## Функции

- Основной бот: проверка идентичности каналов, невидимые UUID с ротацией,
  регистрация защиты через `protect` / `unprotect`, фильтр слов и GIF,
  блокировки, белый список, антифлуд по чатам.
- Панель `/panel`: режимы модерации, логи, судный день, Protected/Super/Signed,
  mute, trust, EXCOMMUNICADO, роли подписантов, отзыв каналов и их shadow-статус.
- Certificates: регистрация через `/reg название`, одобрение администратором,
  ключи через `/start`, подпись inline-сообщений, страницы `/check` и `/shadow`.
  PKCS#8/SPKI PEM и подписываемые байты `user_id:text` совместимы с Python.
- Shadow: невидимые названия каналов, подписки, пробный Plus на календарный месяц,
  московские суточные лимиты, учёт альбомов, архив авторов, магазины через
  Telegram Direct Messages и принятие условий с SHA-256 политики безопасности.
- Экономика: SQLite, баланс, переводы, бонус раз в 12 часов, рынок кодов,
  однократное погашение кодов, API-ключи и их отзыв.
- Logs рассылает посты основного канала подписчикам. Judgment Day удаляет
  поступающие посты и сообщения при активном протоколе; одноразовый код
  подтверждения меняется после использования.
- Jarvis: Gemini, история в памяти отдельно для каждого чата, текст и
  расшифровка голоса, административные действия только для owner/root.
- `/q` / `/quote`: WebP-стикер с текстом, именем и аватаром автора,
  отправляемый в личные сообщения после одобрения.
  `/download` сохраняет текст с Telegram entities или исходный медиафайл
  после одобрения; `/olymp` выводит календарь из `olymps.json`.

Основной бот единолично выполняет модерацию и ротацию каналов. AI-бот отвечает
за диалог и команды; это позволяет запускать их вместе без двойного расхода
Shadow-квот и повторной ротации. AI без основного бота не заменяет защиту канала.
Одновременно запускайте только один экземпляр каждого бота.

## Переход с Python

1. Остановите старые процессы и сохраните резервную копию состояния.
2. Скопируйте `config.json`, `shadow.json`, **`pig6economy.db`**,
   `keys/` и `certificates/` в выбранный `--data-dir` (в Docker — `data/`).
   Перед копированием SQLite остановите все процессы, использующие базу.
   Репозиторный `database.db` не является рабочей базой экономики исходной версии.
3. Перенесите `.env` и проверьте права ботов в Telegram.
4. Выполните `cargo run -- check-config --data-dir data`, затем запустите сервисы.

Неизвестные поля конфигурации сохраняются, отсутствующие получают значения
по умолчанию. Некорректный JSON не заменяется пустым состоянием. JSON-записи
используют блокировку `<имя>.json.lock` и атомарную замену файла, SQLite — WAL
и транзакции. Для ручного редактирования остановите соответствующие сервисы.

Новые `requests.json` и `offsets.json` хранят ожидающие одобрения и смещения
Telegram polling. Старые inline-кнопки с путями `tmp/...` нужно создать заново:
новая версия использует непрозрачные идентификаторы запросов. Старый список
`tmp/allowed_messages.json` автоматически импортируется, если `requests.json`
ещё не создан; при переносе скопируйте и этот файл вместе с остальными данными.

История Gemini начинается заново после перезапуска. При создании цитат
неподдерживаемые шрифтом символы пропускаются; исходная версия также удаляла emoji.
Список олимпиад сохранён; исходные незавершённые настройки и напоминания
не реализованы. EXCOMMUNICADO включает временный протокол судного дня,
пятисекундный отсчёт, отзыв доверия и аннулирование подписи выбранной записи.

## HTTP API

Сохранены страницы и ресурсы сайта. Публичные методы:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка процесса |
| GET | `/api/market` | Цена и количество кодов |
| GET | `/api/history?range=24H` | История, диапазоны 1H/6H/24H/7D/30D |
| GET | `/api/operations` | Последние операции |
| GET | `/api/top?limit=10` | Рейтинг |
| GET | `/api/balance` | Баланс |
| POST | `/api/buy?count=1` | Купить коды |
| POST | `/api/sell?count=1` | Продать коды |
| POST | `/api/pay?username=name&amount=10` | Перевод |
| POST | `/api/bonus` | Получить бонус |

Для баланса, покупок, продаж, переводов и бонуса нужен заголовок
`Authorization: Bearer <ключ из /apikey>`. Неавторизованные запросы получают
HTTP 401; недопустимые операции — HTTP 400 с `detail`, ошибки параметров — 422.
Это исправляет старую выдачу ошибок операций с HTTP 200.
Свечи истории используют реальные сохранённые цены без случайных high/low.

## Проверки

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
```

Тесты используют временные JSON/SQLite и локальные имитации Telegram HTTP API.
Токены, доступ к реальным чатам и Gemini им не нужны. Проверяются
квоты, альбомы, повторы покупок, ротация/откат защиты, права на одобрение,
атомарность финансов, PEM-подписи, веб-маршруты и экранирование HTML.

Внешние интеграции с реальными Telegram-ботами и Gemini нужно проверить
после заполнения `.env`; в этой среде рабочие токены не предоставлены.
